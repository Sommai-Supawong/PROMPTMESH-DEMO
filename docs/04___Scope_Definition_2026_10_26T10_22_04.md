**Project:** Hyperlocal Disaster-to-Commerce (D2C) Mesh

**Stage Owner:** sommai

## 1. Scope Statement

The D2C Mesh pilot delivers a **mobile-first Progressive Web App (PWA)** implementing the three-track pipeline — **เตือนภัยตรงจุด (Track 6) → เดินทางปลอดภัย (Track 5) → เสบียงหมุนเวียนด้วยเงินท้องถิ่น (Track 2)** — for Nakhon Pathom province and the surrounding Bangkok perimeter. The platform serves four user roles (**Resident, Rescue Team, SME/Shop Owner, Donor/Government**) through role-based interfaces unified under a single application. [source: SRS / participant]

**Design Philosophy:**
- **Soft UI** (Apple OS style), rounded, modern design [source: SRS / participant]
- **Clean White** theme with **Solid Blue** primary action buttons (no AI gradients) [source: SRS / participant]
- **"Kanit"** (คณิณ) font system-wide; **minimalist icons** (Material Icons / Lucide / Heroicons) replacing emojis [source: SRS / participant]
- **Mobile-first** responsive design (Mobile + Desktop 100%) [source: SRS / participant]
- **Dashboard/Homepage** entry point (not forced map view), with clear CTA to open the Map [source: SRS / participant]
- **Google Maps API** as base map with D2C Mesh custom layers [source: SRS / participant]
- **Collapsible UI** — all cards, pop-ups, and toolbars can be collapsed/swiped down to maximize map visibility [source: SRS / participant]
- **AI Assistant** via dedicated circular **Floating Action Button (FAB)** with context-aware behavior per screen [source: SRS / participant]

**Integration-over-invention principle:** All payment flows route through existing PromptPay QR / Krungthai Paotang API infrastructure. No proprietary payment gateway is built. Flood data is consumed from existing government agencies (TMD, HII, RID, GISTDA, Traffy Fondue) via API integration — no proprietary physical sensor network is deployed. [source: Stage 2 market research / Stage 3 feasibility / participant]

## 2. Intent Backlog (MoSCoW Prioritization)

All backlog items trace back to the **Intent Statement** (Stage 1): *"Build a hyperlocal AI-powered platform that fuses government flood data into street-level predictions, provides vehicle-aware safe routing, and activates geo-targeted E-Vouchers redeemable at local SME Micro-Relief Stations — creating an end-to-end warning-to-action pipeline that also serves as year-round community commerce infrastructure via อปท. welfare voucher distribution."*

### WON'T HAVE (This Pilot — Explicitly Excluded)

| ID | Excluded Item | Rationale |
|---|---|---|
| **W-01** | **Building our own payment gateway** | We use PromptPay / Krungthai Paotang API exclusively. Thailand's payment infrastructure is mature (74M daily transactions, near-universal QR acceptance) — building a parallel payment system would duplicate existing capability and introduce unnecessary BOT licensing burden [source: Stage 2 market research / Stage 3 constraint C1 / participant instruction] |
| **W-02** | **Deploying our own physical hardware sensor network** | Software-first approach. We consume data from TMD, HII, RID, GISTDA, and Traffy Fondue's existing 4,000+ telemetry stations. Optional low-cost IoT sensors (P2-02) are a future enhancement, not a pilot dependency [source: Stage 2 market research / participant instruction] |
| **W-03** | **Direct BOT e-money license application** | Pursuing Krungthai banking partnership route instead, which eliminates 6–12 month licensing timeline [source: Stage 3 compliance assessment] |
| **W-04** | **Blockchain-based transaction ledger** | While global precedents (WFP Building Blocks, Oxfam UnBlocked Cash) use blockchain, Thailand's centralized PromptPay infrastructure makes blockchain redundant for our use case. Transaction transparency achieved through Krungthai's existing audit trail [source: Stage 2 market research] |
| **W-05** | **Autonomous vehicle / EV-specific routing** | Research confirms no operational system provides flood depth at the centimeter resolution required for autonomous vehicles [source: Stage 2 market research]. We focus on human-driven vehicles with three clearance tiers |
| **W-06** | **National-scale deployment** | Pilot is Nakhon Pathom + Bangkok perimeter only. Multi-province expansion (P2-06) is post-validation |
| **W-07** | **Desktop-first or native app development** | Mobile-first PWA only. Desktop responsive as secondary. Native iOS/Android apps deferred [source: SRS / participant] |
| **W-08** | **AI gradient visual design or emoji-based UI** | Design system mandates Clean White + Solid Blue with Kanit font and icon-only (no emoji) approach [source: SRS / participant] |

## 3. Success Criteria

Measurable outcomes that define "done" for the 12-month pilot. Each criterion is linked to the backlog item(s) it validates.

| # | Success Criterion | Target | Measurement Method | Validates |
|---|---|---|---|---|
| **SC-01** | Flood prediction accuracy at tambon (sub-district) level | ≥70% accuracy on historical validation set (2021–2025 flood events in Nakhon Pathom) | Compare AI predictions against actual flood reports from Traffy Fondue / HII records | P0-01, P0-02 |
| **SC-02** | Alert lead time before flood arrival at user's soi | ≥2 hours average warning time before water reaches predicted level | Timestamp comparison: alert issued vs. actual flood arrival (sensor/crowdsource confirmed) | P0-02, P0-03 |
| **SC-03** | Routing safety — zero incidents of routed vehicles encountering water exceeding their clearance threshold | 0 reported incidents during pilot period | In-app incident reporting (P0-05 `Report Flooded Road`) + post-event user survey | P0-04, P0-05 |
| **SC-04** | Pilot household enrollment | ≥500 registered resident households in Nakhon Pathom | App registration database count | P0-08, P0-11 |
| **SC-05** | Micro-Relief Station merchant enrollment | ≥50 registered SME merchants with active Store Status Tags | Merchant registration database | P0-06, P0-07 |
| **SC-06** | E-Voucher end-to-end transaction success rate | ≥95% of initiated voucher redemptions complete successfully | Transaction log from Krungthai API — failed/completed ratio | P0-07, P0-12 |
| **SC-07** | E-Voucher disbursement-to-redemption speed | ≤30 minutes from fund injection to first merchant redemption | Timestamp: `Inject Funds` action → first `Scan QR to Redeem` completion | P0-07, P1-01 |
| **SC-08** | User engagement during non-flood season (อปท. welfare mode) | ≥30% monthly active users retained from flood-season peak | Monthly active user count (อปท. welfare transactions + app opens) | P1-05 |
| **SC-09** | SME revenue impact | ≥20% increase in monthly transaction volume for enrolled merchants (vs. pre-enrollment baseline) | Compare merchant PromptPay transaction data: 3 months pre vs. 3 months post enrollment | P0-06, P0-07, P1-05 |
| **SC-10** | Offline alert delivery coverage | ≥80% of registered users in affected zones receive alert within 15 minutes (any channel: push, SMS, or community relay) | Cross-reference alert dispatch log with delivery confirmations across all channels | P0-10, P1-04, P1-06 |
| **SC-11** | Government agency data integration | ≥2 agencies (of TMD, HII, RID, GISTDA) providing data via formal agreement | Signed MOUs / active API connections | P0-01, P0-02 |
| **SC-12** | Platform uptime during flood events | ≥99.5% API availability during declared flood events | AWS CloudWatch monitoring + incident log | All P0 features |

## 6. Scope Boundary Summary

**IN SCOPE (12-month pilot):**
- PWA application for 4 user roles in Nakhon Pathom + Bangkok perimeter
- 12 P0 features forming the complete warning-to-action pipeline
- 6 P1 features for pilot enrichment (target: first 3 months post-MVP)
- Integration with PromptPay/Krungthai Paotang via existing APIs
- Consumption of government flood data via API agreements
- Soft UI design system with Clean White + Solid Blue + Kanit font + icon-only approach
- Mobile-first PWA with desktop responsive support

**OUT OF SCOPE (this pilot):**
- Building any proprietary payment gateway (W-01)
- Deploying any physical hardware sensor network (W-02)
- Direct BOT e-money license application (W-03)
- Blockchain transaction ledger (W-04)
- Autonomous vehicle routing (W-05)
- National-scale deployment (W-06)
- Native iOS/Android apps (W-07)
- AI gradient visuals or emoji-based UI (W-08)
